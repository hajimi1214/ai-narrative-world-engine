# 研究到产品的改造记录

本项目把设计笔记转化为独立实现，不将上游源码、文案、视觉资产、提示词或数据库引入生产应用。

## 2026-11-21 — 恢复历史稿为全新工作稿

### 观察来源

- Pagekin 的公开文档描述了章节重新打开、保留已确认稿历史并先检查后续规划影响的工作流：[`notes/pagekin.md`](notes/pagekin.md)。
- BookStack 的公开模型将页面修订保存为独立记录；恢复旧版会创建新的当前版本而非回写旧历史：[`notes/bookstack.md`](notes/bookstack.md)。

### 独立实现

- 从版本列表选中历史稿，逐行展示与当前工作稿的相同、删除和新增内容。
- 只有当前章节与打开的卷可恢复，恢复文本先进入普通编辑框，由作者再次确认保存。
- 保存调用项目现有 `/writer/edit`，用 `AUTHOR_EDIT` 新建版本，旧稿只通过 parent lineage 关联；质量报告失效，新版需要重新审查和批准。
- 复用已有项目/章节权限、乐观并发、自动写作运行暂停要求与封卷守卫。
- 比较行数乘积超过 180,000 时显示有界摘要，避免超长章节触发无界二次方 diff。

### 验证

- API：连续手改多个版本后恢复第一个历史稿，检查旧行未修改、新行编号/父版本正确、当前稿替换且需重新审核；重复请求幂等；陈旧基线、正在写作或已封卷均拒绝。
- diff helper：中文插入/删除、CRLF、空段落和大文本预算。
- 浏览器：选择历史稿 → 查看 diff → 确认恢复 → 查看编辑缓冲区 → 取消或保存 → 对新稿重新审核。
- 响应式：章节阅读、差异区、恢复按钮在 320/390/768/1024/1440/1920 px 检查无横向溢出。

### 边界

这是对自身已实现作者稿版本和并发边界的再利用，并非直接采用外部实现。许可证清单保存在 [`sources.json`](sources.json)。

### 验收结果

- API `test_authoring.py`：11 项通过，包含 HTTP 恢复、父稿 lineage、陈旧基线拒绝、封卷拒绝、旧记录不变和恢复稿重新审核。
- `draft-diff.test.cjs`：3 项通过，覆盖中文插入/删除、CRLF 和超长文本的有界退化展示。
- 浏览器以隔离样例验证：旧稿与现稿差异可见，恢复文本先进入编辑器；保存会带上历史 `base_draft_id` 与当前 `expected_current_draft_id`；新 v4 草稿采用后，旧批准按钮消失并可运行新审核。
- 此轮完整 API 套件通过 1328 项、41 项按条件跳过；前端类型检查和生产构建通过。

## 2026-11-21 — 质量意见定位到正文原句

### 观察来源

Pagekin 的公开说明将审稿意见与作者确认的逐段修稿关联，并要求在改稿前校验来源版本；RAGFlow 的公开文档以原始来源段落验证分析结论。本项目的 critic API 已验证审稿 excerpt 与起止区间来自正文原文，本次把已有精确证据连接到作者工作台。

### 原创实现

- 按正文当前版本的 quality assessment 加载具体 findings。仅当 assessment 的稿件 ID、内容指纹均和当前草稿一致，finding 的 code-point 区间与 `excerpt` 也精确匹配时才显示“跳到正文”；点击时再次检查版本关系。
- Python/SQLite 保存的 Unicode code-point 偏移先映射为浏览器 UTF-16 偏移：非 BMP 表情不会导致选区错位；校验新的 chapter/source/current-draft 由现有 assessment lineage 控制。
- 从意见跳转会把作者现有正文复制进非正式编辑器、焦点移至原句并选中；任何修改仍须作者按“保存工作稿”，生成新版本并重新审查。
- 不注入意见文字以外的模型指令、不自动改写、不静默自动保存；过时摘录不能映射时只提供人工参考。

### 验证

- `finding-span.test.cjs` 覆盖中文、emoji 代理对、CRLF/多行、正文尚未加载、无效/过期摘录和原文尾端范围。
- Playwright 隔离浏览器验证质量意见→跳转→选中原句→编辑/重审路径；六档宽度无页面横向溢出，页内错误为 0。
- 额外构造质量评估与正文稿件指纹不一致的并发情形：界面隐藏跳转按钮并说明重新检查；精确原句仍被正确选中，过期原文不显示跳转。
