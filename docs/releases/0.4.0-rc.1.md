# 0.4.0-rc.1 发布候选验收记录

日期：2026-11-23

## 版本边界

本候选基于前五阶段成果，汇总 Writer 契约与正文证据、候选世界分支、运行恢复与预算提示、中文文学评分基线、作者可选的角色声线设置，以及本阶段的开源和发布配置。版本标识为 `0.4.0-rc.1`，元数据位于 `pyproject.toml`、API 和 Web package。

这是本地候选构建。本阶段没有创建 GitHub Release、版本标签或公开部署。

## 作者主要流程

1. Windows 用户按指南安装 Python、uv、Node.js 和 pnpm，启动本地 API 与 Web 工作台。
2. 用户自行配置模型服务和有限运行预算，然后创建作品并审阅书级方向。
3. 作者检查卷合同与章节任务，按窗口生成正文并运行质量检查。
4. 作者暂停任务后可以编辑工作稿，保存为新版本，再重新审核和批准。
5. 作者确认封卷后保存连续性快照，并可从检查点恢复运行或开始下一卷。
6. 作者可以导出作品备份为恢复副本，也可以导出全部已保存正文或只导出当前仍通过审核的正文。

单元与集成测试使用 Fake Provider 验证创作状态流转，不发起真实模型调用。浏览器使用隔离 SQLite 和合成内容验证页面交互。因没有授权的真实模型额度，本阶段没有声称实际供应商生成已端到端验证。

## 文学效果与成本

文学评测状态仍为 `NOT_EVALUATED`。第四阶段 A/B/C 固定样本方案尚无真实生成正文、人工盲评、Critic 与读者相关性或作者修改时间。第五阶段提示和人物声线改动只有输入传递、过滤、保存和版本指纹的工程测试，没有文学效果对照结果。

真实供应商费用、缺失 usage 时的账单偏差和成本收益比尚未测量。系统显示的 usage 预留不代表供应商实际账单上限。

## 已知限制

- Critic 语义判断仍可能误判否定、反讽、隐含因果或中文对白声线。作者应审阅关键情节和最终正文。
- SQLite 本地单用户模式是当前目标。PostgreSQL、多用户负载和云部署未在此候选中验证。
- 恢复已加密项目密钥依赖原 `AI_CREDENTIAL_MASTER_KEY`。项目备份不包含模型密钥或本机主密钥。
- 遗留历史回放仍可能阻止项目 JSON 备份。报错时先完成历史回放并重新导出。
- 浏览器已有 `/favicon.ico` 404 记录，不影响小说工作流，但会出现在控制台。
- 本地假模型验收不能证明任何实际模型都会按规划创作或生成可直接发布的正文。

## 发布决定

本记录仅标识候选构建。作者仍需在自己的模型服务和隔离作品副本上验证连接、预算和文本体验，然后决定是否创建正式 Release。文学收益结论需等待真实中文读者数据，不能由版本发布替代。
