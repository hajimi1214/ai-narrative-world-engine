# 中文长篇小说工作台使用指南

本指南面向本机单作者使用。主要流程是创建作品、选定方向、规划章节、生成或手改正文、审核采用、封卷、备份并导出。模型生成结果仍由作者决定是否采用。

## 1. 安装与启动

### 环境要求

- Windows 10/11
- Python 3.12
- Node.js 20 LTS
- pnpm 10
- uv 0.11 或兼容版本

首次安装在仓库根目录执行：

```powershell
py -3.12 -m pip install uv
uv sync --locked --extra test --python 3.12
cd apps/web
pnpm install --frozen-lockfile
cd ../..
```

双击 `start-platform.bat`，或在 PowerShell 运行 `.\start-platform.ps1`。启动器会准备本地 SQLite、执行兼容迁移、启动 API 和网页，并在服务未就绪时保留错误日志。

- 作者工作台地址为 `http://127.0.0.1:3000`
- API 健康检查为 `http://127.0.0.1:8000/health`
- 默认数据库为仓库根目录的 `narrative.db`
- 默认 AI 提供方是禁用状态，首次使用前不会自动发起模型调用

PostgreSQL 仅用于开发或专项环境。Compose 服务只绑定到本机地址，并要求在当前 shell 设置非空的 `POSTGRES_PASSWORD`。普通作者无需安装或启动 PostgreSQL。

已有数据库会先备份再升级。保留 `narrative.db`、生成的迁移备份和 `.env`。不要用测试数据库替换真实作品数据库。

## 2. 配置模型

首页的“测试模型”可在创建小说前验证连接。模型请求可能产生供应商费用。确认服务地址、模型名和供应商计费方式后再测试。

生成模型可在本机环境变量或项目的模型设置页配置。项目设置页可将密钥保存为本地加密凭据。保存项目密钥前，先在根目录运行一次：

```powershell
.\scripts\initialize-local-secrets.ps1
```

脚本会把生成的 Fernet 主密钥写入被 Git 忽略的 `.env`，不会把密钥值打印到终端。已配置的主密钥不会被覆盖。该密钥不能从作品备份中恢复。遗失后，已保存的项目密钥无法解密，因此应使用本机受保护的密码管理方式另存一份。

你也可以完全不把提供方密钥存入项目设置，而在启动平台前通过本机环境变量设置 `AI_API_KEY`。不要把真实密钥写进 `.env.example`、Git、截图或问题报告。

向量检索属于可选能力。没有配置 embedding 模型时，仍可使用基本规划和创作工作流。启用前在模型设置页单独测试向量服务。

## 3. 创建作品与确定方向

点击“开始新小说”，选择最接近手头材料的入口：

- **从一句灵感开始**：只有前提或冲突时使用
- **从已有大纲开始**：保留已有结构并补齐整本合同
- **从已有正文继续**：用已有片段规划后续长篇
- **导入世界观**：先建立世界边界
- **空白创作**：逐项填写主题、类型和主角

选择工作方式时：

- **作者主导卷级创作**适合持续写作。作者提供大方向，系统按卷生成当前章节窗口
- **自动导演**由系统推进更多规划与章节环节，默认仍需要作者确认整本方向
- **仅整本规划**先生成方向或规划，不启动连续正文生产

默认按有限 token 预算运行。预算耗尽时任务停在可恢复检查点。只有明确了解计费与运行范围后，才选择不限预算。系统拿不到用量时会标记为未知并预留预算，不能把该值视作供应商账单。

先检查书级前提、叙事视角、主角欲望、故事冲突、结局方向和禁止内容，再确认方向。模型生成的规划不是作者已经确认的设定。

## 4. 规划与连续写作

在整本规划中核对卷目标、故事弧、章节任务、必需事件、禁止揭示和伏笔。章节任务越具体，后续越容易定位偏差。修改书级方向后，应复核受影响的章节任务。

作者主导模式按滚动窗口生成任务。进入章节工作台后可预览 Writer 上下文、生成正文、运行质量检查、生成修复稿或直接编辑工作稿。质量状态和正式采用是两个不同状态。编辑正文会创建新版本，旧质量报告随稿件变化而过期。

作者手改前先暂停正在运行的自动任务。保存后重新运行质量检查，再批准或采用。旧稿仍保留在版本历史中。恢复历史稿会另存为新版本，不覆盖原历史。

“AI 实况”显示运行阶段、最近更新、失败状态和恢复入口。关掉浏览器不会主动取消本机任务。重启 API 后回到原项目导演台查看检查点。若显示等待重试、预算不足或需要作者处理，按页面给出的操作继续、提高预算、重试或接管。

自动跨卷默认关闭。要启用时，在作品级设置中打开后再确认下一卷的目标、冲突、结束状态和连续性承接。系统先封存当前卷并保存快照，再按同一自动运行的剩余预算推进。下一卷信息不完整时，运行会停在原检查点等待补充。

## 5. 审核、采用与封卷

质量报告可以包含必需剧情事件或伏笔回收的正文引用。检查引用是否对应当前稿件版本和实际情节，再决定是否批准。结构化状态和 Critic 的 PASS 都不能代替作者判断。

封卷前核对已采用章节、质量状态、正式世界状态、卷目标和伏笔证据。只有封存后生成的连续性快照才可作为跨卷承接依据。规划中写有结局，不代表正文已经实现该结局。

## 6. 备份、恢复与导出

在“小说安全”页导出项目备份。备份包含作品内容和历史信息，应视为私人创作资料。备份不包含模型 API 密钥，也不包含本机加密主密钥。

恢复时会创建恢复副本，不覆盖当前项目。恢复后先检查作品、章节、历史稿和卷快照，再从副本继续。存在未完成历史回放的项目目前可能无法导出项目 JSON 备份，页面会给出阻止原因。

章节工作台可导出整本或当前卷为 UTF-8 TXT 或 Markdown。可以导出全部已保存正文，也可以筛选为仍通过当前质量审核的稿件。对外发布前，请检查章节顺序、标题、未批准草稿和作品中包含的敏感资料。

除数据库和项目备份外，另行保护 `.env` 中的 `AI_CREDENTIAL_MASTER_KEY`。迁移备份不会替代定期异地备份。

## 7. 常见恢复方式

| 状态 | 操作 |
| --- | --- |
| 模型连接失败 | 检查提供方、地址、模型名、密钥和网络，再手动重试连接 |
| 正在等待自动重试 | 查看预计重试时间。不要重复创建相同任务 |
| 预算耗尽 | 查看已确认用量和未知用量预留，决定是否提高预算后从检查点继续 |
| 质量未通过 | 查看引用和问题正文，编辑或生成修复稿，再运行审核 |
| 来源或指纹过期 | 刷新工作台并重新检查当前大纲、正文和审核状态 |
| API 连接暂断 | 检查 `logs/api.error.log`，恢复服务后回到原运行查看检查点 |
| 密钥库无法解密 | 使用首次配置时保存的主密钥。备份无法替代主密钥 |

不要手工修改数据库来绕过运行状态或质量门。若出现无法恢复的错误，先复制数据库和日志到安全位置，再提交不含小说内容和密钥的错误说明。

## 8. 能力边界

- 软件运行正确、事件证据齐全和质量门通过不等于小说具有文学感染力。
- 当前没有真实读者盲评或跨条件 A/B/C 文学对照结果，不能声称本引擎比简单写作流程写得更好。
- 模型可能误判人物动机、因果、视角和中文语气。作者仍负责最终方向、关键角色决定和发布正文。
- token 预算使用提供方用量或本地保守预留，不是实际账单上限。
- 本地单用户和 SQLite 是本候选版本的支持目标。生产 PostgreSQL、多用户协作、云部署和跨设备同步没有在此候选版本验证。
