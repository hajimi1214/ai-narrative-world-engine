# 第三阶段长篇自动创作可靠性、恢复与成本治理

日期为 2026-11-23。实现基于前两阶段提交和报告复核完成。测试使用合成项目、隔离 SQLite、Fake provider 和本地构建，不读取作者数据库、不使用真实 API Key、不发起付费模型请求。

## 已治理的问题

- OpenAI 兼容 provider 保留供应商实际返回的 usage 字段，不再把缺少的 `usage` 补成零。每个结果记录 `attempts`，内部限流重试也进入调用计数。缺失 usage 的调用带有 `usage_status=UNKNOWN` 和 `unknown_usage_calls`。
- 运行预算同时查看已确认 token 和故障/未知用量预留。未知用量按运行设置的保守预留值计入预算，默认按目标章节字数计算并限制在 1024 至 8192 token。预留不会重复叠加同一个已记录失败调用。
- 全自动导演和作者卷级导演共用模型调用预算围栏。Writer、Critic、Repair、规划、角色行动和世界裁定在调用前检查剩余预算。场景运行每个已完成场景提交用量，失败时保留本次调用用量和错误信息。
- 全自动导演接入持久化租约、检查点和暂时性错误退避。超时、429 和可恢复的 5xx 使用指数退避并保存 `next_retry_at`。同一 worker 周期不会清掉重试等待，重启或租约过期后从同一阶段恢复。达到重试上限后进入 `AUTO_RETRY_EXHAUSTED`，需要作者处理。
- Token 预算耗尽时运行暂停在明确检查点。继续接口要求提交更高预算，且新预算必须同时高于当前预算以及已确认用量和预留量。重复提高预算不会重新生成已提交步骤。
- 默认自动运行使用有限 token 预算。作者可以在首页明确勾选不限预算，默认值不会因为遗漏字段而变成无边界运行。
- 首次模型连接测试与项目模型测试在 provider 请求前检查密钥库。缺少 `AI_CREDENTIAL_MASTER_KEY`、密钥库无法解密或没有生成密钥时，返回可识别的 409 错误，不再出现未处理的服务器异常。项目配置、正文生成和规划使用相同的项目超时、重试和限流设置。
- 运行状态接口和作者工作台显示确认 token、未知调用、预算预留、调用次数、成本未知状态、最近检查点、自动重试时间和恢复操作。没有生成实际成本数字，成本状态保持 `UNKNOWN`。

- Playwright 使用隔离 SQLite 合成作品检查首页、新书向导、项目总览、自动导演预算暂停、当前卷导演、章节工作台和整本规划。320、390、768、1024、1440、1920 CSS 像素下页面 `documentElement.scrollWidth` 均等于视口宽度。320 像素下项目导航可打开。预算暂停页实际显示确认 token、未知 usage 调用、预算预留和提高预算入口。

## 状态边界与遗留风险

- 未知 usage 预留是保守的本地预算策略，不是供应商计费结果。真实账单可能高于或低于预留值。系统会显示“用量待核对”，作者仍应在供应商控制台确认账单。
- provider 内部重试已计入调用次数，但供应商可能在网络断开后已经接受请求而本地没有响应。系统不会把未知请求自动当作已完成章节或正文采用，采用与世界发布仍由持久化检查点和幂等键约束。
- 服务重启恢复验证使用过期 worker 租约和 Fake provider，未模拟 Windows 强制断电、文件系统损坏或供应商真实幂等语义。SQLite 文件仍需要作者定期备份。
- 项目密钥依赖持久化的 `AI_CREDENTIAL_MASTER_KEY`。密钥丢失时系统会阻止使用已保存密钥并显示明确错误，无法从备份中恢复该密钥。备份不包含 provider secret ciphertext。
- 运行成本展示保持 `UNKNOWN`。项目没有供应商账单 API，也没有在本阶段引入价格表，因此不能声称估算成本准确。
- 本阶段没有扩大并发。worker 仍按单本地运行顺序和租约推进，吞吐量优化留待后续有真实运行数据后评估。

## 第四阶段前置条件

- 第三阶段可靠性基线已经完成，第四阶段才能开始文学质量研究或人工评测任务。
- 任何真实多章实验必须使用原创、合成或明确授权文本，冻结模型、提示、参数、预算、失败记录和人工接管规则。
- 真实运行报告应同时提交确认 token、未知调用数、预留量、供应商账单对照、恢复重复率和人工接管位置。未知成本不能用模型自报替代供应商账单。
