# 后续五阶段建议

优先级从高风险、容易造成错误承诺的问题开始。以下是目标效果，不是本轮批准或启动的开发任务。

## 第一阶段：可信的输入与成本边界

作者设定的叙事视角贯穿规划、任务单、场景 POV 与 Writer；输出协议对空正文和缺失字段 fail closed；禁止事件不依赖 Writer 自我申报；provider 缺 usage 时进入可见的“成本未知”并按预留策略停止或保守继续。首次配模型时给出可操作的密钥库配置状态，不能因未配置密钥而落成服务器异常。验收要用无 usage、错误 POV、空 prose、空密钥、缺少主密钥和限流等假 provider 场景覆盖。

## 第二阶段：中文长篇人工质量基准

建立独立于数据库规则样本的中文章节与跨章节评测集，包含人物弧线、因果转折、伏笔、信息揭示、文风差异和坏例。由多位中文读者/编辑盲评，并记录分歧和置信区间；对同一文本用不同顺序、不同 Judge 和人工复核，报告 Critic 与读者判断的逐维相关，而不只报告总分。

## 第三阶段：真实写作任务的长期连续性实验

在合成、原创或明确授权素材上运行多章到多卷的配对实验，对照有/无结构计划、角色记忆检索、正式事实约束与人工审核。检查错误事实率、角色知识泄漏、人物状态回归、章节任务达成、伏笔正确回收、重复与退化、每千字成本以及人工修订时间。报告每一项失败和删失运行，不只展示成功样例。

## 第四阶段：记忆与资料检索的价值审计

为人物认知和研究资料分别测量 Recall@k、Precision@k、错误权威提升率、过期版本泄漏率、token 贡献和端到端写作影响。每次索引/embedding 改造与确定性基线对照。未提高写作质量或降低人工查找成本的检索通道，应关闭或降低复杂度。

## 第五阶段：基于运行证据的架构收敛

收集脱敏的状态转换耗时、恢复重复率、未知用量比、迁移失败、索引失效、人工接管位置和功能使用率。以真实收益决定统一两个导演路径、压缩重复 projection、增强 PostgreSQL/SQLite 支持或简化单作者部署。先给每个保留组件列出责任、数据主权和可重建来源，再做局部演进，不做无基准的大型重构。

本轮交付到此为止。第二阶段及其后续工作没有自动启动。
