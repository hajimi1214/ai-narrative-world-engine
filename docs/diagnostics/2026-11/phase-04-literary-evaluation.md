# 第四阶段中文长篇真实质量评测体系

第四阶段研究与工具工作始于 2026-11-23，本次收尾复核记录采用客户端日期 2026-11-23。本报告是协议与工具交付记录。它不包含真实生成文本、真实读者评分或作者修改实验。

## 使命与当前结论

建立可重复评测流程，分别回答软件是否正确、故事事实是否连贯、文本是否好读、读者是否愿意继续、作者需要花多少时间修改。评测代码只做离线分析，不改变生产 Writer、Critic、质量门或正文采用。

截至本报告，系统只有工程正确性和结构化事实连续性回归证据。文学效果和真实读者体验 **NOT_EVALUATED**。不得声称人物塑造、冲突、情感、中文文风、长篇整体质量或复杂世界引擎优于简单流程。

## 证据分层

| 层次 | 数据来源 | 可以回答的问题 | 不能替代 |
| --- | --- | --- | --- |
| 工程正确性 | 自动测试、状态轨迹、备份与迁移 | 运行和数据边界是否按代码合同工作 | 文本质量 |
| 故事事实与连续性 | 正式事实、角色知识、时间线、正文事件证据 | 正文是否承接记录的故事事实 | 因果张力或人物魅力 |
| 文学表达 | 匿名正文、逐维评价、正文证据 | 人物、情节、语言、章节可读性 | 读者总体偏好 |
| 真实读者体验 | 盲评、弃评、继续阅读意愿、AI 感知 | 读者的体验与选择 | 系统内部 Critic 判断 |
| 成本和作者负担 | token 记录、账单核对、等待和修订时间 | 质量收益是否值得运行和修改成本 | 未知的供应商账单 |

各层分开报告，不折算成一个“小说质量总分”。

## 研究依据

量表把真实读者的叙事投入、写作维度和模型评审作为不同测量对象。Narrative Engagement 研究支持从读者体验角度记录叙事投入，但不是中文长篇自动评分器；WritingBench、G-Eval 和 LLM-as-a-Judge 研究可用于设计写作与 Judge 比较，却不证明模型评分等同于读者偏好；CharacterEval 是中文角色扮演对话基准，不能替代多章人物成长研究；LOT 的故事文本长度和任务也明显短于连载长篇。因此本项目只把相关工作用作量表/协议设计参考，质量结论仍需本项目真实正文与读者数据。[Narrative Engagement](https://doi.org/10.1080/15213260903287259) · [WritingBench](https://arxiv.org/abs/2503.05244) · [G-Eval](https://arxiv.org/abs/2303.16634) · [LLM-as-a-Judge](https://arxiv.org/abs/2306.05685) · [CharacterEval](https://doi.org/10.18653/v1/2024.acl-long.638) · [LOT](https://arxiv.org/abs/2108.12960)

## 量表与盲评

评分量表 v2 有 21 个 1 至 5 分维度，分为人物、情节、表达与结构、故事连续性、读者意愿五组。每个数值评分都需引用正文证据并填信心值。样本不足以判断时填写 `null` 并给出 `score_abstentions` 理由，不猜分。

匿名读者模板中没有条件、任务 ID、模型、prompt 或运行信息。研究者在单独工作区保管任务/条件到匿名文本 ID 的映射。至少两位读者独立评价相同样本，保留缺评与分歧，不用平均分隐藏不一致。

量表、示例文本模板和操作细节见[文学质量量表](literary-evaluation-rubric.md)和[研究者评测说明](../../../research/evaluation/README.md)。

## 冻结任务与对照

冻结的合成 pilot 包含四个任务，每个三章连续窗口，覆盖悬疑、现实情感、历史奇幻和科幻成长。每个任务比较三种条件。

- A 为基础章节规划写作。
- B 使用相同基础 Writer，增加已采用章节摘要和角色记忆。
- C 使用完整世界引擎、角色认知、候选分支、正文审核证据和采用事务。

每项实验需冻结相同模型版本、作者任务、目标篇幅、temperature、top-p、seed、每条件 token 预算和失败策略。每个 task × condition 都必须记录为完成、失败、阻断、中断或未开始。不得仅保留成功样本。

当前代码已提供冻结记录完整性校验与匿名 packet 生成工具。它没有自动启动三个创作条件，也没有内置真实模型实验 orchestration。运行人员仍需先确认三个条件在指定模型和环境中确实可实现且变量受控。若模式差异不可实现，就应停止比较并记录，不可将不等价条件包装成架构因果结论。

## 自动分析

离线汇总覆盖逐维 task 等权条件均值及 task-cluster 标准误、相同评审和样本的配对差值、按原创任务作为独立重抽样单位的 bootstrap 区间、读者间加权 pairwise Cohen's kappa 与 task-cluster 探索区间、AI Judge 相对人类 task 均值的逐维误差和偏差、成功/失败/中断/缺失、下一章意愿、AI 感知、修订时间、确认 token、未知 usage 和预留 token。

- 少于四个独立任务时不生成配对 bootstrap 区间，返回 `INSUFFICIENT_TASKS`。四任务 pilot 的区间仅属探索性，不是功效充分的确认性结论。
- 评审一致性是重叠项目的加权 pairwise Cohen's kappa，并以原创 task 为重抽样单位计算探索性区间。少于五个共享项目不报告区间。该统计不宣称是普遍读者共识。
- 人类评价缺失时状态为 `NOT_EVALUATED`，只有 Judge 时为 `MODEL_ONLY`。
- `provider_cost_status` 始终为 `UNKNOWN`，直到逐次请求与供应商账单完成对账。
- 重复评审行、无效评分、无效引用和不完整生成网格会显式报错或保留缺失，不以最后一条覆盖前值。

模型 Judge 逐维评分必须附正文摘录和 Unicode code-point 偏移。分析器有冻结正文时会核对精确摘录和正文哈希。引用有效只证明摘录位置匹配，不证明 Judge 解释正确。

## 当前运行证据

- 文学评估模块包含 37 项离线协议、盲评、配对统计、揭盲、引用验证、成本和完整性测试，均通过。
- API 全集分成四组执行，覆盖 1477 项，合计 `1436 passed, 41 skipped`。41 项依赖 PostgreSQL 或未配置的外部服务。分组结果为 `307 passed, 2 skipped`、`259 passed, 6 skipped`、`501 passed, 31 skipped`、`369 passed, 2 skipped`。每组使用独立临时 SQLite 数据库。
- Web 工具测试 `22 passed`，TypeScript 类型检查和生产构建通过。没有真实模型 API 请求。
- 浏览器在合成项目、隔离 SQLite 和禁用模型下检查小说库、创建向导、项目导航和章节编辑器。六个视口宽度均无页面级水平溢出，320/390/768 px 导航可键盘开合并恢复焦点。验证细节见[响应式验收记录](../../../logs/usability-qa/phase-04-responsive-2026-11-23.md)及[结构化结果](../../../logs/usability-qa/phase-04-responsive-2026-11-23.json)。
- 当前冻结 pilot 记录保持 `PLANNED`，汇总输出 `NOT_EVALUATED`。没有真实模型输出、真实中文小说语料、独立读者评分、作者修改时间或模型评审记录。
- 因缺乏真实语料和读者，本报告不能回答实际最优秀或最差的文学维度，也不能回答世界状态和角色 Agent 是否改善小说。

证据等级如下

- **已执行工程证据**包括 API/Web 自动化测试、离线协议校验和统计工具测试。
- **研究工具已实现**包括原创任务设计、21 项评分量表、读者盲评包、评分与完整性校验及汇总分析。
- **真实文本证据**尚无 A/B/C 生成语料。
- **真实读者证据**尚无盲评分数、弃评、阅读意愿或修订负担。
- **人类与模型 Judge 一致性证据**尚无配对数据。

## 六项验收问题的当前回答

1. **系统生成的小说在哪些方面真正优秀？** 没有真实生成长篇正文和读者盲评，不能确认任何文学维度优势。事件证据、角色信息边界和检查点只证明工程合同。
2. **哪些文学问题最严重？** 目前无法从真实读者数据排序。人物主动性、人物关系、声音差异、因果、悬念、节奏和中文对白都是待测维度，不是已确认缺陷。
3. **世界状态和角色 Agent 是否改善小说？** 尚未在相同任务和 Writer 条件下比较三章连续正文，无法判断。
4. **完整引擎是否优于简单写作？** 没有 A/B/C 文本和配对读者评分，无法判断。
5. **AI 自评和真实读者是否有偏差？** 核验与分项偏差工具已通过合成数据测试，但没有 Judge 与读者配对记录。
6. **哪些优化最值得投入？** 当前不能按实际表现选择第五阶段文学优化。下一步优先取得冻结条件下的真实文本、至少两位独立评审和修订时间数据，再据低分、分歧和作者负担排优先级。

## 证据限制与后续优化依据

pilot 四个任务不足以支持对中文长篇或特定题材的普遍结论。一任务一文类也不能支撑文类差异判断。需要更多独立任务、多个模型或正式功效设计。

第五阶段不应把没有人评依据的提示改写当作已确认文学弱点。可在冻结 A/B/C 后优先观察人物选择和代价、角色声线差异、因果推进、悬念、中文对白/描写、读者继续阅读意愿和作者修订负担。实际低分与高修改成本共同出现的维度，才具有优先优化证据。

仓库已有第五阶段人物声线与写作提示改动及工程记录，但它们没有盲评或文学效果结果。本次收尾只完成第四阶段评测方案和工具，没有执行或扩展第五阶段。后续若使用此量表，需先冻结具体实验与批准的模型预算，并招募独立读者。
