# AI Narrative World Engine

一个面向作者的本地长篇小说生产工作台。

它不是“输入一句话，生成一段正文”的聊天窗口，而是把一本长篇小说拆成可检查、可暂停、可恢复的生产过程：自动评估整本方向并选择最高分方案，再规划卷、故事弧、章节和场景，随后让角色 Agent 在自己的认知范围内行动，最后生成、审核、修复并自动采用正文。

项目适合希望在本机长期写作的单个作者。默认使用 SQLite，不要求安装 PostgreSQL 或独立向量数据库即可启动；模型通过 OpenAI 兼容接口接入，生成模型和向量模型可以分别配置。

## 项目目标

长篇小说最容易失控的地方不是某一段文字，而是写到几十章以后出现：

- 角色知道了本来不该知道的秘密；
- 时间线前后矛盾，人物在同一时间出现在两个地点；
- 伏笔没有回收，或者回收前就被正文提前说破；
- 章节没有完成原本的任务，故事只是在“看起来发生了什么”；
- 人物、世界事实和关系状态没有从上一章传递到下一章；
- 正文出现模板化、解释过度、空泛景物和明显的 AI 腔。

本项目把这些问题当作系统状态和质量门，而不是只交给作者凭感觉返工。模型负责提出方向和文本，平台负责保存上下文、记录证据、检查约束，并把每次生成留下可追溯的运行记录。

## 核心能力

### 1. 作者友好的开书入口

第一次打开首页不会强制填写小说表单。作者可以先查看平台能做什么，也可以先测试模型连接，再决定如何开始：

- 从一句灵感开始；
- 粘贴已有大纲或世界观资料；
- 导入已有正文片段；
- 先建立空白项目，稍后再规划。

开书向导会用普通写作语言解释每个字段，不要求填写 JSON。FULL_AUTO 提交后先生成三套整本方向并做结构化评分，自动选择最高分方案后进入卷、章节和正文生产；作者可通过接管功能修改方向。

### 2. 整本规划与章节任务单

规划器保存的是一套可继续继承的书级合同，而不是一次性摘要：

- 故事前提、类型、读者和叙事视角；
- 主线、长期对立、故事弧和卷战略；
- 章节标题、章节目标、冲突、转折和场景安排；
- 伏笔方向、前段承诺、结局方向和文风约束。

每章都有任务单。正文 Writer 必须先根据任务单组织场景节拍，再让角色做出行动，最后把行动写成正文。章节审核会检查任务是否完成，而不是只看字数。

### 3. 每个角色一个 Agent

角色 Agent 不是简单的角色简介。每个角色可以维护：

- 当前目标、恐惧、关系和行动倾向；
- 已知事实、未知事实和错误认知；
- 长期记忆、短期记忆和最近经历；
- 当前地点、时间、状态和可执行动作。

角色行动会进入导演和场景执行链。系统会检查角色是否使用了超出认知范围的信息，并把已采用的结果写回角色心智和世界状态。

### 4. 世界、时间线、因果和连续性

小说项目拥有自己的世界事实、事件、状态快照和因果账本。生成前会为当前章节构建上下文，生成后会验证：

- 时间顺序是否成立；
- 角色位置是否冲突；
- 物品、伤势、关系和事实状态是否发生非法跳变；
- 伏笔是否被提前泄露、长期失踪或错误回收；
- 本章产生的新状态是否能成为下一章的输入。

发现问题时，系统可以生成修复候选，而不是直接覆盖原正文。作者可以查看证据、编辑候选、采用或放弃。

### 5. Writer、审核、修复和采用

单章生产链包含以下阶段：

1. 读取书级规划、卷级上下文和本章任务单；
2. 生成场景节拍和角色行动；
3. 生成正文草稿；
4. 执行连续性、结构、文风和反 AI 质量检查；
5. 对可修复问题生成修复草稿；
6. 质量门通过后自动采用正文，并回灌世界、角色、时间线和伏笔状态；质量未通过的草稿不会进入正式历史。

草稿、审核报告和修复稿都有独立版本。未通过质量门的内容不会悄悄变成正式正文。

### 6. 反 AI 文风约束

平台支持项目级写作 Bible 和反 AI Bible。规则可以用于生成前约束，也可以用于生成后的统计和检查，重点关注：

- “首先、其次、最后”等模板化连接；
- 过度使用“仿佛、似乎、不禁、命运的齿轮”等高频套话；
- 空泛且不推动剧情的风景描写；
- 连续解释人物已经通过行动表现出来的情绪；
- 大量同构句式、重复对话和段落节奏；
- 不必要的总结、升华和作者旁白；
- 词语选择、标点和句式统计异常。

规则不是把正文改成统一的“反 AI 模板”，而是把问题标记出来，交给 Writer 和作者结合语境处理。风格样本可以作为项目长期参考，生成和审核会同时读取这些样本及其约束。

### 7. RAG 与研究资料库

项目支持世界资料、研究资料、角色资料和正文历史的长期检索。检索链路包含：

- 关键词/BM25 检索；
- 向量语义召回；
- RRF 混合排序；
- 来源、片段和命中理由显示；
- 上下文预算控制，避免把整本书无差别塞进模型。

研究资料可以单独建立研究块向量索引。向量模型与正文生成模型分开配置，便于使用阿里百炼等免费或可替换的 embedding 模型。

### 8. AI 创作实况

进入小说工作台后，顶部有常驻的“AI 实况”入口。它会轮询项目执行记录，显示当前或最近的：

- 导演规划；
- 角色行动；
- 世界裁定；
- 正文写作；
- 章节审核；
- 问题修复；
- 保存场景和自动推进。

实况面板显示进行中、已完成、失败和已暂停状态，方便作者判断平台是在思考、等待模型、需要处理问题，还是已经完成。它是阶段级运行状态，不承诺 token 级逐字流式输出。

## 推荐创作流程

```text
首页
  -> 查看功能 / 测试模型
  -> 新建小说向导
  -> 生成并选择整本方向
  -> 整本规划
  -> 卷与故事弧
  -> 章节任务单
  -> 场景节拍
  -> 角色 Agent 行动
  -> Writer 生成正文
  -> 连续性与反 AI 审核
  -> 修复候选
  -> 作者采用
  -> 状态回灌，进入下一章
```

建议不要跳过整本规划直接连续生成正文。长篇稳定性的关键，是让每一章都有明确任务，并让上一章的结果成为下一章的正式状态。

## 快速开始：作者模式

### 环境要求

- Windows 10/11；
- Python `>= 3.11`；
- Node.js `>= 18`，推荐 Node.js 20 LTS；
- pnpm `>= 9`；
- 一个可用的 OpenAI 兼容生成模型接口；
- 一个可用的 OpenAI 兼容 embedding 接口（没有向量检索需求时可以稍后配置）。

### 一键启动

在项目根目录双击：

```text
start-platform.bat
```

或者在 PowerShell 中运行：

```powershell
.\start-platform.ps1
```

脚本会自动准备本地 SQLite、启动 API 和网页、检查服务，并打开浏览器。

默认地址：

- 网页：http://127.0.0.1:3000
- API：http://127.0.0.1:8000

日志位于项目根目录的 `logs/`：

```text
logs/api.log
logs/api.error.log
logs/web.log
logs/web.error.log
```

### 首次安装依赖

如果仓库还没有 `.venv`：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
```

安装前端依赖：

```powershell
cd apps/web
pnpm install
cd ../..
```

之后再次使用 `start-platform.bat` 即可。

## 模型配置

### 推荐的生成模型配置

首页点击“测试模型”即可在创建小说前测试，不会创建项目，也不会保存正文。模型配置页还会在进入时自动测试已保存的连接。

| 项目 | 值 |
| --- | --- |
| Provider | `openai_compatible` |
| Base URL | `https://tokenrhythm.studio/v1` |
| Model | `deepseek-v4-pro` |

API 密钥只应填在本机环境变量或页面密码输入框中。不要把真实密钥写进 README、截图、Git 提交或备份文件。

### 环境变量配置

可以在项目根目录 `.env` 中配置默认值。仓库不应提交包含真实密钥的 `.env`：

```env
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://tokenrhythm.studio/v1
AI_API_KEY=你的生成模型密钥
AI_WRITER_MODEL=deepseek-v4-pro
AI_DIRECTOR_MODEL=deepseek-v4-pro
AI_CHARACTER_MODEL=deepseek-v4-pro
AI_WORLD_MODEL=deepseek-v4-pro
AI_CRITIC_MODEL=deepseek-v4-pro
AI_REPAIR_MODEL=deepseek-v4-pro
AI_TIMEOUT_SECONDS=120
```

单用户本地创作可以让导演、角色、世界、Writer、审核和修复共用同一个 DeepSeek 模型。

### 向量模型配置

向量模型单独配置：

```env
AI_EMBEDDING_PROVIDER=openai_compatible
AI_EMBEDDING_BASE_URL=https://your-embedding-provider.example/v1
AI_EMBEDDING_API_KEY=你的向量模型密钥
AI_EMBEDDING_MODEL=你的embedding模型名
AI_EMBEDDING_DIMENSION=1024
```

进入项目的“模型与记忆检索”页面后，可以测试生成连接、测试向量连接、查看索引状态并重建记忆索引。向量额度用完时，替换 embedding 模型后重新测试并重建索引即可。

## 工作台说明

| 工作台 | 用途 |
| --- | --- |
| 总览 | 查看当前小说状态、进度和推荐的下一步 |
| 整本规划 | 管理故事主线、卷、故事弧、章节和任务单 |
| 导演台 | 查看导演提案、角色行动、世界裁定和自动推进 |
| 章节 | 生成正文、审核、修复和采用章节草稿 |
| 角色 | 管理角色档案、Agent 目标、认知和记忆 |
| 世界实体 | 管理地点、势力、物品、规则和世界事实 |
| 研究资料库 | 保存资料、研究块、来源和检索内容 |
| 模型与记忆检索 | 配置生成/向量模型，管理检索索引 |
| 小说安全 | 备份、导入、恢复和查看恢复点 |

进入小说工作台后，顶部“AI 实况”会保持可见。作者不需要切换到开发者日志查看模型是否还在工作。

## 连续性检查清单

建议用一部固定测试小说做回归，至少包含：

- 10 个核心角色；
- 20–30 条世界事实；
- 10 条剧情线程；
- 3 个故事弧；
- 30–50 章测试大纲；
- 20 个时间线事件；
- 10 个伏笔和回收点；
- 每个角色的已知、未知和错误认知；
- 5–10 段认可的中文文风样本。

每次修改 Writer、Prompt、写作规则或模型配置，都应使用同一套基线回归，重点验收角色认知、时间顺序、位置冲突、伏笔状态、章节任务完成度，以及重复/模板化/AI 痕迹分析。

测试基线位于：

```text
apps/api/tests/golden_novel_fixture.py
apps/api/tests/GOLDEN_NOVEL_BASELINE.md
```

## 备份、导入与恢复

本地数据库默认是项目根目录的 `narrative.db`。完成一卷、大规模修改世界观、采用关键章节或更换模型前，建议在“小说安全”页面导出备份。

支持：

- 导出整部小说备份；
- 查看备份状态和恢复点；
- 导入备份为新的恢复副本；
- 对已有项目创建恢复副本，不直接覆盖原项目。

模型 API 密钥不会作为小说正文内容导出。备份仍可能包含完整小说、世界观和角色资料，请按私人创作资料保存。

## 测试与构建

## 自动导演模式

系统保留两种本地单用户模式：`FULL_AUTO` 继续使用原有无人值守流程；`AUTHOR_GUIDED_VOLUME` 由作者负责书名、主题、总体大纲、剧情走向和主角设计，AI 按卷补全世界、角色、卷纲、章节任务、场景、正文、质量审核和连续性。作者模式只生成当前卷的滚动窗口（默认 5 章，最多 10 章），不会在开书时生成整本书的详细章节，也不会把章节预估值当作完成上限。

作者模式入口为卷总览 `/projects/{project_id}/volumes` 和当前卷导演台 `/projects/{project_id}/director/volume`。作者可以继续、暂停、扩展、封存或解封当前卷，也可以在窗口中提交指导意见、增加人物或修改主线。影响分析只标记未写且未锁定的章节；已采用正文和已封存卷会显示为保护范围。当前卷完成条件满足后，系统只提出封存或全书完结建议，默认等待作者确认。

自动导演页面位于 `/projects/{project_id}/director/auto`，卷级导演台位于 `/projects/{project_id}/director/volume`，每 2 秒从 API 轮询最新检查点。页面刷新或 API 重启后，任务会从数据库中的最近步骤继续。暂停、继续、重试和接管都不会删除已有产物；重复请求使用 `idempotency_key` 返回原运行。

运行状态中的 `PAUSED` 表示作者主动暂停或人工接管，`FAILED` 表示阶段可重试的失败，`BLOCKED` 只用于无法修复的结构化输出、质量门未通过、状态冲突、连续模型失败或数据库损坏。文风、局部重复和低优先级审核问题会留在章节质量债务中，不会阻塞整本运行。SQLite 升级由 Alembic 执行，升级前会生成带时间戳的 `*.migration-backup-*.db` 备份。

每章会按章节结构配置拆成一个或多个独立场景检查点，因此自动运行记录中的场景运行数可能高于已完成章节数；这些检查点用于断点恢复，不要求作者逐个操作。服务重启后重新打开自动导演页面即可继续查看并推进最近的运行。

```powershell
# 后端完整测试
.\.venv\Scripts\python.exe -m pytest -q apps/api/tests

# 前端类型检查与生产构建
cd apps/web
pnpm exec tsc --noEmit
pnpm build
```

回归测试覆盖模型网关、开书向导、整本规划、角色 Agent、时间线和因果、Writer、质量门、反 AI 规则、RAG、研究资料、自动推进、恢复和备份等模块。

## 常见问题

### 双击后没有打开浏览器

查看 `logs/api.error.log` 和 `logs/web.error.log`，也可以手动访问 `http://127.0.0.1:3000`。如果 3000 或 8000 端口被占用，关闭占用进程后重新启动。

### 模型测试失败

检查 Base URL 是否是 OpenAI 兼容 API 的 `/v1` 地址、模型名是否可用、密钥是否过期或额度耗尽，以及供应商是否允许当前网络访问。

### 向量检索失败，但正文可以写

生成模型和 embedding 模型是两个独立通道。先确认生成模型，再单独检查 embedding 地址、模型名和维度。暂时不需要 RAG 时，可以先完成整本规划和正文生产，之后再配置向量索引。

### 修改正文后质量状态变成过期

质量报告绑定正文、规划和写作 Bible 的版本。正文、规则或规划改变后，旧报告不能代表当前内容，系统会要求重新审核。

### AI 实况一直显示进行中

AI 实况来自项目执行记录，每约两秒刷新一次。先等待一个模型超时周期；如果确认任务已经停止，刷新页面并检查自动推进状态和 API 错误日志，不要在未确认状态前重复提交同一任务。

## 当前边界

当前版本专注于“本地单用户长篇小说”。暂不把漫画、短剧、多用户协作、云端账号和公开部署作为主流程。系统可以帮助提高一致性、叙事组织和文本质量，但不能保证模型每次都写出完美文学作品；作者仍应审核整本方向、关键角色决定和最终正文。

## 后续方向

- 扩大中文反 AI 规则和风格统计样本；
- 提高研究块 embedding 的持久化和混合召回质量；
- 增加更细的章节回放、错误证据和质量趋势；
- 降低作者从灵感到第一章的操作成本；
- 让自动推进在模型失败和额度切换时更容易恢复。
